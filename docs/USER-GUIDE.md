# LESR 本地工作台使用指南

## 启动

在 PowerShell 中运行：

```powershell
lesr web PROJECT
```

`PROJECT` 可以是空的 LESR 工程，也可以是已经建立配置的工程目录。
命令会显示一个仅可使用一次的 `127.0.0.1` 地址；在本机浏览器打开即可。
页面闲置 15 分钟会自动锁定，重新启动命令会生成新的地址。

## 只有自然语言需求时

进入“从需求开始”，直接粘贴原始需求。无需提前编写规范、选择 Profile、填写 UID 或理解 Git 提交。

LESR 会：

1. 根据需求信号选择经过逐字节核对的 GitHub Spec Kit 或 arc42 模板组合；
2. 保留用户原句并自动生成 Human Key；
3. 先自行处理可调查或可采用保守默认值的内容；
4. 一次最多显示一个涉及安全、授权或许可证的实质问题，并给出推荐答案；
5. 经一次明确人工确认后，为空工程建立受保护的本机身份、初始配置和可编辑草案。

这一步不会安装软件、下载模型、修改 PATH、删除现有内容或发布正式 Revision。草案仍要经过“校验并提交审阅”、人工签名和 Apply 才能成为正式工程内容。

## 日常工作

- “从需求开始”：把还没有规范化的需求整理成可编辑工程草案。
- “查找规范”：输入 Human Key 或自然关键词，查看类型、正文摘要和关系概览。
- “相关资料”：选择工程配置，输入目标 Human Key，再选择任务；系统自动整理必读、参考和缺口。
- “发起变更”：按名称选择配置和本机身份，填写 Human Key、内容与变更理由，然后送审。
- “审阅与批准”：批准人只需核对变更范围、理由、校验结论和角色要求，再作人工确认。
- “发布基线”：对已写入的完整配置执行检查、人工批准和发布。

## 什么信息需要关注

普通用户主要关注：

- Human Key；
- 工程配置名称；
- 变更范围；
- 变更或批准理由；
- 是否存在阻止保存的问题；
- 谁应当批准，以及批准是否完成。

Commit、UID、Hash、Delegation UID、原始请求和原始返回由系统自动处理。
它们只集中显示在“审计详情”，用于审计或故障排查，不是日常操作步骤。

## 锁定与私钥

网页只监听本机回环地址。点击右上角“锁定”会立即结束当前会话。
批准签名由一次性本机签名进程完成；网页和 MCP 均不会展示或取得私钥。
