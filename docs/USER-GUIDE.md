# LESR 本地工作台使用指南

## 启动

在 PowerShell 中运行：

```powershell
lesr web PROJECT
```

`PROJECT` 可以是空的 LESR 工程，也可以是已经建立配置的工程目录。
命令会显示一个仅可使用一次的 `127.0.0.1` 地址；在本机浏览器打开即可。
页面闲置 15 分钟会自动锁定，重新启动命令会生成新的地址。

## 建立工程规范

进入“从需求开始”，选择一种方式：

- “描述需求”：直接粘贴现有需求；
- “导入规范文件”：选择已有的 Markdown 或 PDF 规范。

LESR 根据内容选择一组固定上游模板，而不是生成自有文档骨架。通用需求由 GitHub Spec Kit 组织；系统架构、REST API、事件消息、数据科学、模型说明、嵌入式实时需求、安全威胁模型和架构决策会分别补充 arc42、OpenAPI、AsyncAPI、Cookiecutter Data Science、TensorFlow Model Card、NASA FRET、OWASP Threat Model Library 或 MADR。系统随后按目标、功能、约束、测试和交付内容分组，并生成 Human Key。点击“建立工程草案”后即可继续编辑和送审。

工程执行限制、来源判定和本机身份配置由运行时处理，不作为建立草案前的用户问答。只有真正改变产品范围或预期结果、且无法从现有内容判断的选择，才会出现在界面中。

## 日常工作

- “从需求开始”：粘贴需求或导入自定义规范，整理成可编辑工程草案。
- “查找规范”：输入 Human Key 或自然关键词，查看类型、正文摘要和关系概览。
- “相关资料”：选择工程配置，输入目标 Human Key，再选择任务；系统自动整理必读、参考和缺口。
- “发起变更”：按名称选择配置和本机身份，填写 Human Key、内容与变更理由，然后送审。
- “审阅与批准”：批准人只需核对变更范围、理由、校验结论和角色要求，再作人工确认。
- “发布基线”：对已写入的完整配置执行检查、人工批准和发布。

## 什么信息需要关注

普通用户主要关注：

- Human Key；
- 工程配置名称；
- 变更范围；
- 变更或批准理由；
- 是否存在阻止保存的问题；
- 谁应当批准，以及批准是否完成。

Commit、UID、Hash、Delegation UID、原始请求和原始返回由系统自动处理。
它们只集中显示在“审计详情”，用于审计或故障排查，不是日常操作步骤。

## 锁定与私钥

网页只监听本机回环地址。点击右上角“锁定”会立即结束当前会话。
批准签名由一次性本机签名进程完成；网页和 MCP 均不会展示或取得私钥。
