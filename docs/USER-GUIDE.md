# LESR 本地工作台使用指南

LESR 把一次工程目标组织成 Mission，并由代理完成资料整理、编辑、校验、测试和集成。
用户主要查看工程结构、工作进展和真正需要取舍的事项。

本指南描述 2.0 产品线的默认交互。功能完成与发布状态以当前版本的代码、测试和发布
记录为准。

## 启动

在 PowerShell 中运行：

```powershell
lesr web PROJECT
```

`PROJECT` 可以是空工程，也可以是已经建立规范和配置的工程目录。终端显示本机地址后，
在浏览器打开工作台。

## 开始一个工程

可以从两种材料开始：

- 直接描述目标、约束和验收要求；
- 导入已有 Markdown 或 PDF 规范。

LESR 根据内容选择固定版本的上游模板组合，而不是临时生成一套文档骨架。通用需求采用
GitHub Spec Kit；系统架构、API、事件消息、数据科学、模型说明、嵌入式实时需求、威胁
模型和架构决策按场景加入 arc42、OpenAPI、AsyncAPI、Cookiecutter Data Science、
TensorFlow Model Card、NASA FRET、OWASP Threat Model Library 或 MADR。

系统保留用户原话，并把内容放入模板与 Profile 定义的工程区域。已有自定义规范不会被
模板替换；模板补齐结构，来源仍能回到导入材料。

## 查看工程地图

工程地图不是固定的功能按钮集合。它根据当前 Profile 显示项目实际采用的区域：例如
SYS/SWE/SUP，或目标/需求/架构/实现/验证/发布。选择一个区域后，可以继续查看：

- 内容树与正文；
- 上下游关系和追踪覆盖；
- 当前 Mission 涉及的变化；
- 校验、测试和证据状态；
- 尚未覆盖或存在冲突的位置。

每项内容都有可读名称；工程编号用于精确查找，例如 `REQ-SW-0142`。搜索框同时支持自然
关键词，不要求用户先知道编号。

## 跟进 Mission

Mission 页面展示目标、当前里程碑、工作包依赖和代理进展。代理可以分别处理需求、架构、
实现、验证与集成；一个工作包等待材料时，其他不依赖它的工作仍可继续。

常规编辑、资料查找、校验、测试、修复、检查点和无冲突合并由后台完成。阶段性结果集中
到一个里程碑中呈现，用户不需要在计划刚开始时一步一批。

## 处理工程决定

“待决定”只收集会改变结果或承载正式责任的事项。每项决定显示：

- 决定类型和工程区域；
- 当前目标与需要决定的原因；
- 变更范围；
- 对需求、设计、测试、证据和交付物的影响；
- 校验结论与不确定性；
- 推荐方案、实质不同的备选以及选择后的结果。

材料工程取舍可以在这里直接选择。Profile 指定的偏离、例外、正式基线或发布责任会在材料
完整后进入人类签名。代理授权表示系统可以在既定范围内继续工作，不作为人类批准显示。

## 版本与审计

“版本”展示已经形成的工程状态、变化摘要和基线。普通页面使用工程名称、区域、范围和
理由说明结果。Git 提交、内部资源标识、内容摘要和协议数据集中在审计详情中，供追溯与
故障排查。

模板来源见 `zero-spec-intake-sources.md`，产品决策规则见
`AGENTIC-PRODUCT-CONTRACT.md`。
