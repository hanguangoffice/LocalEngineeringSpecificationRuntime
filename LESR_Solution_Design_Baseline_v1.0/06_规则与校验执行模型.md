# 06 规则与校验执行模型

**决策成熟度：FOUNDATIONAL；规则后端 PROVISIONAL**

## 1. 规则来源

规则来自用户启用的 Profile、项目规范、Tailoring 和有效 Deviation。LESR 核心只保留身份、完整性、权限和历史保护等不可绕过安全不变量。

---

## 2. 规则类型

Structural、Relational、Lifecycle、Process、Applicability、Normative、External Mapping、Context、Consistency、Confidentiality、Delegation、Baseline 和 Provenance。

---

## 3. 结果

```text
PASS
FAIL
NOT_APPLICABLE
INDETERMINATE
SUPPRESSED_BY_VALID_DEVIATION
RULE_ERROR
NOT_EVALUATED
```

`INDETERMINATE` 和 `RULE_ERROR` 不能自动视为通过。

---

## 4. Observation 与 Issue

Validator 每次运行产生 Immutable Observation。项目规范决定是否创建 Issue、是否阻止 Transition、是否允许 Deviation 或仅作为信息。

---

## 5. 执行阶段

Ingestion、Workspace Edit、State Transition、Pre-Apply、Post-Apply、Context Planning、Baseline Creation、Audit 和 Delegation Check。

---

## 6. 规则后端候选


SHACL/Rego 通过实验决定。

---

## 7. AI 检查

AI 质量检查默认产生 Advisory Observation。只有用户规范明确授权时，才参与门禁，并保存模型、提示、输入 Revision 和置信信息。

## 8. 与 Normative Model 的关系

Validator 只产生 Evaluation Outcome 和 Observation。是否阻止 Draft、Review、Apply、Approve 或 Baseline，由 Rule 的 Enforcement 映射决定。

Criticality 和 Priority 只能用于风险和排序，不能自动覆盖 Modality 或 Enforcement。

未解决的 Normative Conflict 产生 INDETERMINATE，不允许 AI 自行选择规则。

## 10. v1.0 规则执行基线

- Applicability 使用三值逻辑；
- Constraint AST 有静态类型与单位；
- Rule Outcome 使用封闭集合；
- Enforcement 按 Operation 映射；
- Rule Compiler 输出 Explanation Map；
- Fixture 是可执行 Rule Revision 的必要组成；
- 未解决 Authority Conflict 阻止高风险操作。
