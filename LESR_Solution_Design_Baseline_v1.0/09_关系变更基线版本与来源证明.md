# 09 关系、变更、基线、版本与来源证明

**决策成熟度：FOUNDATIONAL；Git 映射细节 PROVISIONAL**

## 1. Relation Assertion

每条正式关系拥有 relation logical ID、relation revision ID、predicate、source、target、assertion kind、state、scope、rationale、evidence 和 provenance。

---

## 2. Endpoint Binding

### Logical Binding

指向 Logical ID，在当前 Configuration 中解析。

### Pinned Binding

指向准确 Revision，用于 Approval、Evidence、Audit 和 Baseline。

### Fragment Binding

指向准确父 Revision 的 Fragment，用于精确注释和来源定位。

### External Binding

指向外部 URI、Git Object、File、Code Symbol、标准条款或工具对象。

---

## 3. Baseline

必须冻结 Object Revision、Relation Assertion Revision、Profile、Tailoring、Deviation、Effective Model、Git Commit 和 Integrity Hash。

Logical Binding 在 Baseline 中必须可解析为准确 Revision。

---

## 4. Relation 生命周期

proposed、active、rejected、retired、superseded。

更改 predicate、endpoint、rationale 或 binding 产生新 Revision。

反向名称由 Relation Type 计算。

---

## 5. Asserted 与 Inferred

Inferred Relation 默认不能满足正式追踪，必须经 Promotion 才能成为 asserted。

---

## 6. Change Workspace

固定 Base Configuration、Object Revision、Relation Revision、Effective Model、Delegation 和 Operations。

Apply 生成新 Revision、Change Record、Provenance、Git 更新和投影更新。

---

## 7. Git 映射

Workspace Working Copy 不属于正式 Revision；提交评审后形成的 Candidate Revision 是不可变正式资源。Applied Change 必须产生确定性 Git 差异。Baseline 必须引用 Git Commit。Applied Change 与 Commit 是否严格一对一由原型决定。

---

## 8. 回滚

通过新 Change 恢复旧语义，不删除历史。

## 9. Relation Type 详细语义

Core Relation Role、Profile Relation Type、身份字段和 Formal Trace Credit 见 `09A_关系角色谓词与追踪语义.md`。

## 10. 身份与生命周期

- Logical Object 与 Revision 分离；
- Approval、Evidence、Baseline 使用 Pinned Binding；
- 普通长期工程关系默认 Logical Binding；
- Effective Revision 必须在明确 Configuration 中解析；
- 不使用模糊 current。

## 11. Working Copy

Change Workspace 持有可变 Working Copy。Submit Review 或 Apply 后生成不可变 Revision，Working Copy 不原地升级为正式版本。

## 12. Provenance

Applied Change 必须记录 Base、Operations、Validation、Approval、Delegation、Context Bundle、AI/User/Tool 角色和 Git Commit。

详细设计见：

- `04C_身份命名空间别名与血缘模型.md`
- `08A_WorkingCopyRevision与GitCheckpoint.md`
- `09B_生命周期有效版本与配置解析.md`
- `09C_来源证明责任与审计模型.md`

## 13. v1.0 配置与评审

- Effective Revision 由 Evaluation Context 解析；
- Review Package 固定 Candidate、Relation、Impact、Validation 和 Effective Model；
- Approval 绑定 Package Hash；
- Rebase 或语义变化后旧 Approval 失效。

详见 `09D_EvaluationContext配置与EffectiveResolution.md` 和 `09E_ReviewPackage评审意见与批准模型.md`。


## 14. 生命周期状态投影

Revision Maturity 与 Logical Object Disposition 由不可变 Lifecycle Record 投影，详见 `09F_生命周期事件与状态投影.md`。
