# 03 概念架构与实现边界

**决策成熟度：FOUNDATIONAL；实现后端 PROVISIONAL**

## 1. 已接受的总体形态

LESR 采用：

```text
Git-backed Semantic Runtime
+ Compiled Effective Model
+ Rebuildable Query Projections
+ Context Planner
+ Change Workspace
+ Semantic Transaction
+ Replaceable Interaction Adapters
```

它不是增强 Markdown 文档库、数据库中心 ALM、纯事件系统或纯 RDF 图系统。

## 3. 逻辑组件

### Semantic Registry

定义 Core Resource Class、Facet、Kind、Relation Role、类型、单位和命名空间。

### Profile Compiler

把 Profile、Tailoring、Authority、Exception、Deviation 和规则源编译为 Effective Model。

### Policy Resolver

解析 Applicability、Authority、Conflict、Deviation 和 Enforcement。

### Query Broker

组合精确解析、结构过滤、全文、图遍历和可选向量候选。

### Context Planner

构建可解释 Context Contract，明确 Mandatory、Unknown、Conflict 和 Completeness。

### Change Workspace

承载 Working Copy、Checkpoint、Validation、Impact 和 Review Package。

### Semantic Transaction Engine

以原子方式应用对象、关系、记录、配置和 Baseline 变化。

### Provenance/Audit

记录 Agent、Activity、Input、Output、Approval、Delegation 和 Git 映射。

### Git Integration Boundary

构建确定性 Git Tree 和 Applied Change Record；文件布局不得反向支配领域模型。

---

## 4. 已否决的最终形态

- Markdown + RAG 作为核心；
- 固定数据库表复刻 Codebeamer；
- AI 直接写文件；
- 万能 `Artifact.attributes`；
- UI 先行；
- 向量数据库决定规则和版本；
- Git Commit 直接等于 Revision 或 Approval；
- RDF/图数据库作为不可替换唯一事实源。
