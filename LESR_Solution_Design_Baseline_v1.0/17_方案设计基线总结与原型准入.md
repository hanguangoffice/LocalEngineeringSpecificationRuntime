# 17 方案设计基线总结与原型准入

**状态：DESIGN BASELINE**

## 1. 设计目标已经收敛

LESR 不是文档生成器、通用 RAG、Markdown 管理器或轻量 Codebeamer 复制品。它是：

> 一个由 Git 支撑的本地工程语义运行时。用户定义规范，LESR 负责身份、版本、关系、规则编译、上下文规划、受控变更、评审批准、来源证明和 AI 接口。

## 3. 原型前不得推翻的原则

1. 不能用文件路径代替身份。
2. 不能用 Git Commit 代替对象 Revision。
3. 不能用单一 status 混合成熟度、有效性和配置成员。
4. 不能用单一 severity 混合模态、执行后果和关键性。
5. 不能把未知适用性当作不适用。
6. 不能把 External Tool suppression 当作批准偏离。
7. 不能让 AI 直接写 Approved/Baselined 状态。
8. 不能让查询数据库成为唯一事实源。
9. 不能让 Profile 默认执行任意代码。
10. 不能让普通 Permission 静默覆盖 Prohibition。
11. 不能让审批绑定模糊的“当前版本”。
12. 不能让未解决冲突由 AI 自行选择。

## 4. 进入原型的设计门

开始实现任何长期保留代码前，必须完成四个可删除原型。

### Gate A：语义表达

证明同一模型能表达：

- ASPICE-like 追踪和工作产品；
- MISRA-like 规则、Finding 和 Deviation；
- CAN 接口信号；
- 项目流程规则；
- Fragment Promotion；
- 拆分与合并。

### Gate B：Rule Compiler

证明：

- Rule Source 可编译为 Canonical AST；
- Applicability 三值逻辑确定；
- 类型和单位可检查；
- 冲突可解释；
- Test Fixtures 可自动运行；
- 无任意代码执行。

### Gate C：Configuration 与 Context

证明：

- Baseline、Variant、Workspace Overlay 可以解析；
- Effective Revision 唯一或明确失败；
- Mandatory Context 零漏召回；
- 过期内容不会混入；
- 选择理由完整。

### Gate D：Semantic Transaction

证明：

- 多对象、多关系原子 Apply；
- Working Copy Checkpoint 可恢复；
- 并发 Base 变化被检测；
- Review Package Hash 可验证；
- Git 失败和投影失败可恢复；
- 历史 Revision 不被覆盖。

## 6. 原型失败时的调整原则

- 若 Facet 模型过于复杂，可减少 Facet，但不能回退到任意属性袋。
- 若自定义 Rule AST 不足，可映射到 SHACL/Rego，但仍保留领域层。
- 若 Git Checkpoint 噪声过高，可改变 Git 映射，但不能取消可恢复要求。
- 若关系表性能不足，可更换图投影，但不能改变 Relation Assertion 语义。
- 若 MCP 客户端差异过大，可提供降级适配器，但不能泄漏内部存储。
- 若 UI 需要文档式编辑，可提供 View/Projection，不得让文档结构取代语义对象。

## 7. 方案阶段结束条件

本基线已经达到：

- 核心概念完整；

- Git 和事实源定位明确；
