# 14 原型实验计划

**状态：PROTOTYPE PLAN BASELINE**

## 1. 原型原则

- 每个原型回答一个明确问题；
- 默认可删除；
- 不形成长期兼容承诺；
- 使用真实汽车软件和自定义规范场景；
- 记录失败和错误类型；
- 通过 Gate 后才冻结实现选择。

---

## P1 Semantic Kernel

验证：

- Core Resource Class；
- Facet；
- Kind；
- UID/Human Key/Alias；
- Revision；
- Fragment Promotion；
- Relation Assertion；
- Observation/Issue；
- Process Definition/Activity。

数据集：

- 30 个需求/设计/测试对象；
- 20 条 MISRA-like 规则；
- 20 个 CAN Signal；
- 10 个 Change/Deviation/Evidence。

通过标准：

- 无核心特例；
- 类型明确；
- 拆分、合并和提升可追溯；
- 关系绑定正确；
- 人工可理解。

---

## P2 Rule Compiler

验证：

- Rule Source；
- AST；
- 三值 Applicability；
- 类型和单位；
- Relation Path；
- Aggregate；
- Authority；
- Exception/Deviation；
- Fixtures；
- Explanation Map。

比较：

- 自定义 AST；
- JSON Schema 组合；
- SHACL 1.2 Core 投影；
- 可选 Rego；
- 注册 Validator。

通过标准：

- 四类规范可表达；
- 无任意代码；
- 冲突确定；
- 解释完整；
- Fixture 自动运行；
- 性能可接受。

---

## P3 Configuration and Context

任务：

- MQTT 重连代码修改；
- CAN Signal 范围修改；
- Requirement 变更；
- 测试设计；
- Deviation 评审。

比较：

- grep；
- FTS；
- Vector RAG；
- Relation Query；
- Full Context Planner。

指标：

- Mandatory Recall；
- Precision；
- Staleness；
- Conflict Recall；
- Token；
- Completeness；
- AI Task Outcome。

通过标准：

- 强制规则零漏召回；
- 旧版本不混入；
- Unknown 明确；
- Selection Trace 可读；
- 预算不足时不伪装完整。

---

## P4 Git Canonical State and Transaction

验证：

- Snapshot；
- Applied Change；
- Workspace Checkpoint；
- Candidate Revision；
- Review Package；
- Approval；
- Multi-resource Apply；
- Idempotency；
- Crash Recovery；
- Foreign Diff；
- Projection Rebuild；
- Semantic Merge/Rebase。

Windows 场景：

- 文件占用；
- Unicode；
- 长路径；
- 杀毒软件干扰；
- 进程中断；
- Git 并发。

通过标准：

- 无半状态；
- 历史不覆盖；
- Checkpoint 可恢复；
- Query DB 删除后可重建；
- 外部修改不会静默成为正式事实。

---

## P5 MCP Adapter

至少验证两个客户端。

比较：

- 细粒度工具；
- 中粒度能力；
- Resources + Tools；
- 长任务降级；
- 大正文分页；
- 错误恢复；
- 客户端能力差异。

通过标准：

- Agent 能正确选择能力；
- 无需底层文件 grep；
- 写操作具备 Workspace、Base 和幂等；
- 不暴露任意文件/SQL/Shell；
- 协议版本可替换。

---

## P6 Interoperability

最小验证：

- ReqIF 导入；
- SARIF 导入；
- Codebeamer 导出映射；
- Excel Dataset；
- Git Commit/Tag；
- OSLC 风格 URI。

目标是验证内部模型不阻碍互操作，不追求完整标准合规。
