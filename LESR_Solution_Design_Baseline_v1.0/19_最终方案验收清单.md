# 19 最终方案验收清单

## A. 定位

- [ ] LESR 被描述为语义运行时，而非 Markdown/RAG/ALM 克隆。
- [ ] 用户规范是规则和严格度来源。
- [ ] Git 是必需基础设施。
- [ ] 实现技术仍保持可逆。

## B. 对象

- [ ] Composite、Atomic、Fragment、Field 边界明确。
- [ ] Fragment Promotion 有血缘。
- [ ] UID、Human Key、Alias、Revision 分离。
- [ ] 身份不依赖路径、模块和状态。

## C. 关系

- [ ] Relation Assertion 是独立资源。
- [ ] Binding 类型明确。
- [ ] Formal Trace Credit 明确。
- [ ] 推断关系不自动成为正式追踪。

## D. 规则

- [ ] 原文和 AST 共同版本化。
- [ ] Applicability 三值逻辑。
- [ ] 类型、单位和 Path 可检查。
- [ ] Modality 与 Enforcement 分离。
- [ ] Permission 不自动覆盖 Prohibition。
- [ ] Tailoring、Exception、Deviation 分离。
- [ ] Rule Fixture 可测试。
- [ ] Profile 不携带任意代码。

## E. 配置与上下文

- [ ] 高风险操作具有 Evaluation Context。
- [ ] Effective Revision 可解释。
- [ ] Partial Configuration 不伪装完整。
- [ ] Mandatory Context 不由向量决定。
- [ ] Context Bundle 有完整性状态。

## F. 变更与审批

- [ ] AI 修改 Working Copy。
- [ ] Checkpoint 可由 Git 恢复。
- [ ] Review Package 不可变。
- [ ] Approval 固定 Package Hash。
- [ ] Rebase 后旧审批失效。
- [ ] Apply 是原子事务。

## G. 权威状态

- [ ] Git Commit Tree 保存权威状态。
- [ ] Snapshot 与 Applied Change 一致。
- [ ] Query DB 可删除重建。
- [ ] 外部手改进入 Reconciliation。
- [ ] Baseline Manifest 固定 Effective Model。

## H. 来源和安全

- [ ] Git、Audit、Provenance 分工。
- [ ] AI、用户、工具责任角色分离。
- [ ] AI 不能批准自身正式输出。
- [ ] Prompt Injection 不能扩大权限。
- [ ] 外部工具 suppression 不等于 Deviation。
- [ ] 默认不保存隐藏推理。

## I. 原型准入

- [ ] P1 Semantic Kernel 范围明确。
- [ ] P2 Rule Compiler 范围明确。
- [ ] P3 Configuration/Context 指标明确。
- [ ] P4 Git Transaction 恢复测试明确。
- [ ] P5 MCP 至少两个客户端。
- [ ] 原型代码默认可删除。

## J. 最终判断

只有 A～I 均满足，才生成最终 Codex 工程施工规格。
