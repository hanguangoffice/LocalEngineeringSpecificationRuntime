# 11 标准互操作与外部工具边界

**决策成熟度：PROVISIONAL**

## 1. 原则

LESR 不需要完整实现所有标准。应区分内部语义借鉴、导入导出、API 兼容和完整服务端合规。早期主要采用前两种。

## 2. MCP

MCP 用于将领域能力暴露给 AI 客户端。设计要求是领域层不依赖 MCP SDK、适配器可升级、不把工具列表当核心模型，并考虑稳定规范与新扩展的兼容层。

## 3. ReqIF

ReqIF 适合与传统需求工具交换需求对象、属性和关系。映射候选：SpecObject 到 Artifact、SpecRelation 到 Relation、SpecType 到 Profile Kind、AttributeDefinition 到 Facet Field、Specification 到 Document/View。

难点包括富文本、工具扩展、类型映射、ID 保持、往返不丢失和附件。

## 4. OSLC

OSLC RM、AM、QM、CM 的资源身份、跨生命周期 Link 和配置管理思想值得借鉴。早期可以借鉴 URI 和资源语义，不必完整实现 RDF 服务端。

## 5. JSON Schema

适合结构校验和接口 Schema。需要固定方言版本，并为 Profile Schema 自身提供验证。它不能独自表达全部关系和流程规则。

## 6. SHACL

SHACL 可作为图约束候选。稳定版本和发展中的新版本需要区别对待；若采用，应锁定明确版本，不能依赖未稳定草案作为核心承诺。

## 7. SARIF

SARIF 适合导入静态分析 Rule、Result、Location、Message、Tool、Run 和 Suppression。Suppression 只能成为候选抑制或偏离信息，不能自动等同批准偏离。

## 8. PROV-O

可借鉴 Entity、Activity、Agent 关系，保证来源证明未来可映射。内部不要求采用 OWL/RDF。

## 9. OpenAPI

未来 REST 可以使用 OpenAPI 描述，但 REST 只是适配器，MCP 与 REST 应共享应用层行为测试。

## 10. 外部工程工具

候选包括 Git、clang-tidy、cppcheck、PC-lint、Polyspace、Coverity、pytest、CMake、CANoe、Excel Dataset、Codebeamer 导出和 ReqIF 工具。

适配器只能读取授权数据、提交规范化 Observation/Evidence、调用受控 Change，不能直接写核心投影。

## 11. 标准内容与版权

Profile 可以保存规则 ID、用户自写解释、项目适用性、工具映射、合法持有内容的本地引用和来源元数据；不应随工具分发商业标准全文。

## 12. 互操作成熟度

```text
L1 Reference：记录外部 ID 和来源
L2 Import：单向导入
L3 Round-trip：可保真导出
L4 Conformant Service：完整标准服务
```

MVP 不应默认追求所有标准的 L4。

## 13. 未决问题

1. ReqIF 优先级；
2. OSLC 是否需要 REST 兼容；
3. JSON-LD 是否作为交换格式；
4. SHACL 是否进入核心；
5. SARIF 抑制如何映射；
6. 外部 ID 冲突；
7. 富文本；
8. 往返保真；
9. Profile 许可证；
10. MCP 版本兼容策略。
