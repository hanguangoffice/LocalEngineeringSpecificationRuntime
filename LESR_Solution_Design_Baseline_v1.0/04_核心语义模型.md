# 04 核心语义模型

**决策成熟度：FOUNDATIONAL；序列化细节 PROVISIONAL**

## 1. 语义模型的基本结构

LESR 使用两级开放性：

```text
封闭的 Core Resource Class
+ 可组合 Core/Extension Facet
+ Profile 定义的 Kind
```

Core Resource Class 决定身份、可变性、版本和治理语义；Facet 决定能力；Kind 提供领域名称和组合约束。

---

## 2. 核心资源类别

### 2.1 Governed Object

可独立治理、拥有 Logical ID、Revision 和生命周期的工程语义对象。

例：Requirement、Coding Rule、Component、Interface、Signal、Test Case、Decision、Process Definition、Deviation、Issue、Profile Definition。

### 2.2 Immutable Record

表示已经发生的观察、执行、证明或确认。创建后正文不可修改，纠正通过 `supersedes`、`retracts` 或新记录完成。

例：Test Execution、Static Analysis Observation、Validation Observation、Activity Record、Approval Attestation、Audit Event、Evidence Record。

### 2.3 Change Workspace

隔离候选语义变化的操作资源。它固定基准 Configuration，保存 Draft Revision、Relation 提案、校验和审批条件。

### 2.4 Configuration Snapshot

冻结一组准确 Revision 和 Effective Model。例：Baseline、Release Configuration、Audit Configuration。

### 2.5 Presentation Resource

组织和呈现语义对象，但不自动产生规范效力。例：Collection、View、Published Document、Traceability Matrix、Architecture Diagram。

### 2.6 Supporting Resource

Relation Assertion、Addressable Fragment、External Reference、Principal 和 Source Anchor。

---

## 3. Kind

Kind 是 Profile 中的命名语义配方，例如：

```text
software_requirement
coding_rule
can_signal
test_case
design_decision
deviation_request
static_analysis_issue
```

Kind 定义 Core Resource Class、必需 Facet、可选 Facet、字段 Schema、允许 Relation、生命周期、规则和默认 View。

---

## 4. Facet

Facet 是能力契约，而不是任意字段集合。每个 Facet 定义语义、字段、不变量、允许操作、关系需求和可适用的 Core Resource Class。

---

## 5. Finding 的拆分

### Observation

不可变记录：工具或 Validator 在特定 Revision 上观察到某个结果。

### Issue

可治理对象：项目需要跟踪、分析和处置一个或多个 Observation。

关闭 Issue 不修改原 Observation。

---

## 6. Process 的拆分

- Process Definition：用户规范中的流程定义；
- Activity Record：某次实际执行记录；
- Workflow State：对象当前治理状态。

---

## 7. Verification 的拆分

- Verification Plan：Test Case、Review Checklist、Analysis Method；
- Verification Execution：一次执行；
- Evidence：执行结果和证明。

---

## 8. Decision 与 Approval

Decision 是 Governed Object。Approval 是固定到某个 Revision 和差异哈希的 Immutable Attestation。

---

## 9. Deviation

Deviation 是具有授权作用的 Governed Object。只有满足用户规范定义的审批和有效条件后，才进入 Effective Model。

Deviation 不等于 Tool Suppression、Issue Closed、Warning Ignored 或 AI 建议。

---

## 10. 事实与推断

所有资源和 Relation 标识来源类型：

```text
authored
imported
observed
asserted
inferred
proposed
generated
```

推断内容不能自动满足正式门禁。

---

## 11. 继承策略

内核不使用领域多继承。Profile Kind 通过 Facet 组合表达多重语义。

---

## 12. 当前接受结论

- Core Resource Class 是封闭集合；
- Kind 是开放集合；
- Facet 以组合代替领域继承；
- Extension Facet 必须命名空间化；
- Extension Facet 不得重定义核心身份、Revision、不可变性和审批语义；
- Observation 和 Activity Record 默认不可变；
- Presentation Resource 不承担隐含规范效力。

## 13. 身份与版本

每个 Governed Object 同时具有：

- Internal UID；
- Human Key；
- Logical Object；
- 不可变 Revision；
- 可选 Alias；
- Lineage。

Working Copy 属于 Change Workspace，不是正式 Revision。Fragment 只在准确 Revision 内寻址。

详细设计见 `04C_身份命名空间别名与血缘模型.md`。

## 14. 生命周期三维模型

生命周期分解为：

- Revision Maturity；
- Logical Object Disposition；
- Configuration Membership。

Approved、Effective 和 Baselined 是不同概念。详细设计见 `09B_生命周期有效版本与配置解析.md`。

## 15. 来源证明

Git、Audit 与 Provenance 分工明确。AI 参与时分别记录发起、执行、授权、评审、批准和持久化角色。详细设计见 `09C_来源证明责任与审计模型.md`。
