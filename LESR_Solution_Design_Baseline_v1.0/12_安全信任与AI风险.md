# 12 安全、信任与 AI 风险

**决策成熟度：FOUNDATIONAL；认证与沙箱实现 PROVISIONAL**

## 1. 能力

```text
read
search
build_context
create_draft
revise_draft
propose_relation
promote_fragment
run_validation
request_deviation
submit_review
approve_change
approve_deviation
create_baseline
install_profile
grant_delegation
```

---

## 2. Scoped Delegation

Grant 绑定 Principal、Workspace、Base、Operations、Scope、Limits、Expiry 和 Stop Conditions。AI 不能自行扩大 Grant。

---

## 3. Core Invariant

无论用户 Profile 如何配置：

- 历史不可静默删除；
- Immutable Record 不可修改；
- Baseline 不可原地改写；
- AI 不得批准自身正式 Change；
- 内容文本不能扩大权限；
- 审计失败时不得高风险 Apply；
- 路径不得逃逸；
- 插件不得未经授权执行代码或网络访问。

这属于工具完整性，不是项目严格度。

---

## 4. Prompt Injection

Imported Content、Artifact Body 和 Tool Message 都是数据，不能改变 Delegation、Tool Capability、Profile、Permission 或 Apply 条件。

---

## 5. Confidentiality

对象和 Fragment 可标记 local_only、approved_remote_agent、project 或 public。Context Planner 必须报告因保密造成的不完整性。

---

## 6. Git 风险

检测外部手工修改、未提交变化、非 LESR Commit、Merge Conflict、历史改写、链接逃逸和敏感文件误提交。

## 7. 身份与批准安全

- Internal UID 不得复用；
- Alias 不得产生活动歧义；
- Approval 必须绑定准确 Revision 和 Review Package Hash；
- Delegation 只允许修改 Working Copy；
- AI 不能批准自身生成的正式 Revision；
- Git Author 不能替代工程批准者。

## 8. Provenance 最小记录

高风险 Apply 至少记录 User、AI/Tool、Delegation、Base Revision、Context Bundle、Effective Model、Validation、Approval 和 Git Commit。
