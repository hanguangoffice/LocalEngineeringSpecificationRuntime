# 09C 来源证明、责任与审计模型

**决策成熟度：FOUNDATIONAL；序列化与认证 PROVISIONAL**

## 1. 三个不同系统

### Git

回答仓库中的结构化状态如何变化。

### Audit

回答系统在何时执行了哪些操作。

### Provenance

回答某个 Entity 由哪些输入、活动和参与者产生。

三者必须互相引用，但不能互相替代。

---

## 2. Provenance 核心概念

### Entity

- Object Revision；
- Relation Assertion Revision；
- Immutable Record；
- Context Bundle；
- Effective Model；
- Change Record；
- Baseline；
- Review Package。

### Activity

- Author；
- Generate；
- Edit；
- Import；
- Validate；
- Review；
- Approve；
- Apply；
- Promote Fragment；
- Create Baseline；
- Retract Record。

### Agent

- User；
- AI Agent Session；
- External Tool；
- Adapter；
- LESR System；
- Organization Role。

---

## 3. 责任角色

一次活动可记录：

```text
initiated_by
    发起任务的人或系统

performed_by
    实际执行活动的 Agent

on_behalf_of
    Agent 在谁的授权下执行

reviewed_by
    完成评审的人或角色

approved_by
    承担正式批准责任的人

persisted_by
    将结果写入 Canonical State 和 Git 的系统

observed_by
    产生 Observation 的工具或 Validator
```

这些角色不能压缩为单个 `author`。

---

## 4. AI 参与模型

示例：

```yaml
activity_id: ACT-014
activity_type: revise_requirement

initiated_by: USER-001
performed_by: AI-SESSION-008
on_behalf_of: USER-001
delegation_id: DEL-004

used:
  - REQ-SW-001@5
  - CTX-018
  - EFFECTIVE-MODEL@hash

generated:
  - REQ-SW-001@6

reviewed_by:
  - USER-001

persisted_by: LESR-SYSTEM
git_commit: a83f...
```

它表达：

- AI 是实际生成者；
- 用户是发起者和授权者；
- 用户是否评审和批准独立记录；
- LESR 负责持久化；
- 使用的 Context 与 Effective Model 可追溯。

---

## 5. AI 会话身份

AI Agent 应至少记录：

- provider；
- model identifier；
- client；
- session ID；
- tool capability version；
- Delegation；
- local/remote execution classification。

不要求保存模型隐藏推理。

---

## 6. Context Provenance

Context Bundle 本身是可追踪 Entity，记录：

- Task；
- Target；
- Baseline；
- Effective Model；
- Mandatory Read Set；
- Supporting Set；
- Exclusions；
- Selection Trace；
- Completeness；
- Token Budget；
- 敏感性过滤。

这样可以判断 AI 使用的是哪一版规范。

---

## 7. Audit Event

Audit Event 是不可变记录，至少包含：

```text
event_id
timestamp
actor
operation
target
workspace
request_hash
result
before_hash
after_hash
policy_decision
git_reference
correlation_id
```

Audit 记录调用事实，不必复制所有业务正文。

---

## 8. 用户 Prompt 与聊天内容

默认记录：

- 任务摘要；
- 结构化输入；
- Context Bundle ID；
- 产生的操作；
- 输出 Revision。

默认不强制记录：

- 完整聊天；
- 无关上下文；
- 隐藏推理；
- 敏感自由文本。

用户规范可要求保存完整 Prompt，但需明确保密和保留策略。

---

## 9. External Tool

外部工具产生 Observation 时记录：

- Tool Name；
- Version；
- Configuration；
- Rule Pack；
- Input Revision；
- Execution Environment；
- Start/End Time；
- Result Hash；
- Adapter Version。

Tool Suppression 仍不等于批准 Deviation。

---

## 10. Git Author 与工程责任

Git Author/Committer 只能表示仓库写入身份，不能替代：

- 内容作者；
- AI 生成者；
- 评审者；
- 批准者；
- Apply 执行者。

LESR Provenance 应引用 Git Commit，但不从 Commit Metadata 推断全部责任。

---

## 11. 来源证明不变量

1. Approval 必须能追溯到准确 Revision；
2. Applied Change 必须能追溯到 Base、Operations、Validation 和 Approval；
3. AI 输出必须记录 Delegation；
4. Observation 必须记录执行工具和输入版本；
5. Baseline 必须记录生成活动和 Effective Model；
6. Provenance Record 不可原地修改；
7. 纠正通过新 Record；
8. 审计不可写时拒绝高风险 Apply；
9. Git Commit 不得成为唯一 Provenance；
10. 不保存模型隐藏推理。

---

## 12. 当前已接受结论

- 使用 Entity–Activity–Agent 思想；
- 责任角色分离；
- AI 生成者、用户授权者和批准者分离；
- Context Bundle 进入 Provenance；
- Git、Audit、Provenance 三者并存；
- 默认不保存隐藏推理和全部聊天；
- 外部工具结果记录工具版本和输入 Revision。
