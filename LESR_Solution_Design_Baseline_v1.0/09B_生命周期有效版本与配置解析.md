# 09B 生命周期、有效版本与配置解析

**决策成熟度：FOUNDATIONAL；Variant/时间 DSL PROVISIONAL**

## 1. 生命周期的三维分解

LESR 不使用单一 `status` 同时表示成熟度、有效性和配置成员资格。

### 1.1 Revision Maturity

某个准确 Revision 的治理成熟度。

Profile 可定义具体状态，内核至少理解：

```text
working
candidate
in_review
approved
rejected
withdrawn
```

### 1.2 Logical Object Disposition

逻辑对象整体的使用状态：

```text
active
deprecated
superseded
retired
```

Disposition 与某个 Revision 是否 Approved 分离。

### 1.3 Configuration Membership

某个 Revision 是否被某个 Baseline、Release 或 Variant 配置选择。

Membership 是 Configuration Snapshot 的关系，不是 Revision 自身永久字段。

---

## 2. Approved、Effective 与 Baselined

### Approved

准确 Revision 已获得所需批准。

### Effective

在给定上下文中，系统解析后应采用的 Revision。

Effective 依赖：

- Configuration；
- Baseline；
- Variant；
- Profile；
- 时间；
- Workspace；
- 用户选择。

### Baselined

某准确 Revision 被某个 Baseline Manifest 选中。

同一 Approved Revision 可以不在任何 Baseline 中，也可以被多个 Baseline 选择。

---

## 3. 禁止模糊 current

API 和查询必须明确请求：

```text
latest_revision
latest_approved
workspace_candidate
baseline_selected
effective_for_context
revision_at_time
```

`current` 若无解析上下文，应返回歧义错误。

---

## 4. 多版本并存

系统正式支持：

- 一个或多个历史 Approved Revision；
- 当前 Baseline 使用的 Approved Revision；
- 一个或多个并行 Workspace Candidate；
- Rejected 或 Withdrawn Revision；
- 不同 Variant 使用不同 Revision。

不得以“最新 Revision”自动覆盖已生效配置。

---

## 5. Profile 生命周期职责

用户 Profile 决定：

- Revision Maturity 状态；
- 状态转换；
- Required Checks；
- Approval Role；
- Deviation；
- Blocking Finding；
- 生效条件。

LESR 内核只维护：

1. Revision 不可变；
2. Approval 固定 Revision；
3. Baseline 固定 Revision；
4. Working Copy 不能静默替换 Effective Revision；
5. AI 不能批准自身正式输出；
6. 转换必须留下 Provenance；
7. 身份不复用；
8. 失败转换原子回滚。

---

## 6. Approval Attestation

Approval 是 Immutable Record，至少固定：

```yaml
approval_id: ...
subject_revision: ...
review_package_hash: ...
effective_model_hash: ...
approved_by: ...
approval_scope: ...
conditions: ...
timestamp: ...
```

内容变化后，旧 Approval 不自动适用于新 Revision。

---

## 7. Logical Object Disposition

### Deprecated

仍可解析和使用，但不建议用于新工程。

### Superseded

已由明确后继对象替代，需提供 Lineage Relation。

### Retired

不再允许进入新 Configuration，但历史 Baseline 继续可解析。

### Active

允许用于当前工程。

Disposition 变化通过 Change 进行，并且不修改历史 Revision。

---

## 8. Record 撤回

Immutable Record 不能修改或删除。错误记录通过：

```text
retracted_by
superseded_by
corrected_by
```

连接到新 Record。

---

## 9. Relation 生命周期

Relation Assertion 拥有独立 Revision 和状态：

```text
proposed
active
rejected
retired
superseded
```

更改端点、Predicate、Binding 或 Scope 时创建新 Assertion Revision。

---

## 10. Effective Revision 解析

建议解析顺序：

```text
1. 显式 Workspace Candidate
2. 显式 Baseline / Configuration
3. Variant 或时间条件
4. Latest Approved，且 Logical Object 仍可用
5. 无法唯一解析则 INDETERMINATE
```

解析结果必须返回理由和使用的配置。

---

## 11. 当前已接受结论

- 生命周期采用三维分解；
- Approved 不等于 Effective；
- Baselined 是配置成员关系；
- 多个 Draft Candidate 可以并存；
- 不使用模糊 current；
- Approval 固定准确 Revision；
- Disposition 作用于 Logical Object；
- Immutable Record 通过新 Record 纠正。
