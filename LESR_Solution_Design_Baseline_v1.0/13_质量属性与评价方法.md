# 13 质量属性与评价方法

**决策成熟度：FOUNDATIONAL**

## 1. 质量优先级

```text
语义正确性
> 数据完整性
> 可解释性
> 可恢复性
> 可维护性
> AI 使用效果
> 性能
> UI 美观
```

## 2. 语义正确性

评价状态、版本和基线是否严格区分，Profile 合并是否确定，Relation 方向是否一致，偏离是否只在作用域内生效，推断和事实是否分离。

测试包括模型不变量、Property-based tests、冲突矩阵、版本迁移和随机关系图。

## 3. 数据完整性

必须验证原子应用、失败恢复、投影重建、哈希、并发、文件损坏、中途终止和 Git 外部修改。

## 4. 可解释性

系统应能回答为什么规则适用、为什么变更被拒绝、为什么 Artifact 进入上下文、为什么 Finding 被偏离抑制、哪个 Profile 提供字段、当前有效规则如何产生。

## 5. AI 使用效果

建立固定任务集：代码修改、需求影响分析、规则查询、测试设计、偏离评审和合规检查。

比较：

```text
纯 grep
普通 RAG
LESR 精确查询
LESR Context Planner
```

指标包括强制规范漏召回、无关内容、任务正确率、工具调用次数、token、过期内容和未经允许的写操作。

## 6. 可恢复性

验证删除查询数据库后重建、从 Baseline 和版本恢复、工作区失败恢复、Profile 升级失败回退、外部导入重复执行和部分文件损坏隔离。

## 7. 性能

目标先以体验为准：精确读取近实时、常规搜索可交互、上下文构建在合理时间完成、全量校验可显示进度、大任务可取消。不要为了性能牺牲解释信息。

## 8. 可维护性

评价新 Profile 是否无需改内核，新 Relation Type 是否声明式，新适配器是否只依赖公共端口，核心模型是否有过多特例，文档与代码契约是否同步，错误码是否稳定。

## 9. 可迁移性

验证完整导出、导入新环境、更换数据库投影、MCP SDK 升级、Profile 版本升级以及 Windows 路径处理。

## 10. 设计阶段评价门

在生成最终实现规格前，至少应满足：

1. 核心模型能表达两个明显不同的 Profile；
2. Profile 冲突有确定结果；
3. 三个真实任务能构建合理 Context Bundle；
4. Change Workspace 能表达多对象变更；
5. Baseline 能准确冻结版本和 Profile；
6. 两种存储候选完成对比；
7. MCP 原型证明能力边界合理；
8. 未决高风险问题下降到可接受范围。
